## Scope and authority stance

This register reconciles three approved evidence layers before any v0.5 substrate recommendation is drafted:

1. **Source intent** from Phase A source-map rows and the parent PRD.
2. **Brownfield behavior** from current `pi-chart` implementation/test crosswalk rows, as evidence only.
3. **Patient corpus pressure** from `patient_001` through `patient_005` atlas rows and caveats, as fixture/scenario evidence only.

It also consumes the approved hot/warm/cold access model and substrate packs 05-10. The goal is to decide whether each meaningful substrate recommendation should be carried forward as `adopt`, `revise`, `defer`, `reject`, or `open-question`.

Boundary stance:

- No source, schema, test, patient, `_derived`, package, lockfile, ADR, design asset, `pi-ledger`, or `pi-sim` internal edits are authorized.
- No vector store, embedding, graph index, OpenBrain architecture, backend service, runtime infrastructure, access-plane API, or storage layout is selected.
- No direct agent accepted-write policy is authorized.
- Any ledger implication is a future **chart/adapter** requirement only, never a new `pi-ledger` kernel requirement.
- Hidden `pi-sim` state, simulator oracle truth, evaluator labels, and runtime transcripts are not valid chart truth.
- Rendered/prototype/design evidence can inform chart-digging questions only; it cannot define canonical substrate.
