# Agent-native gap audit

Status: rescue review artifact

Purpose: identify where conventional EHR rails are insufficient for bounded AI-agent navigation and context curation.

| Gap ID | Current workflow pain | Agent-native opportunity | Clinician-facing value | Existing EHR rail affected | Prototype evidence | Risk | Proposed next artifact |
|---|---|---|---|---|---|---|---|
| GAP-001 | A chart exposes many facts but not a task-specific, bounded packet saying why each fact matters now. | ContextPacket compiled from TaskFrame, evidence refs, included claims, omissions, budget, and freshness. | Faster review with less missed context for a specific clinical task. | Patient/encounter, notes, vitals, labs, orders | v0.5 ContextPacket planning; `contextBundle`; `memoryProof` | Premature packet shape becomes another summary blob. | ADR: ContextPacket and ContextReceipt contract |
| GAP-002 | EHRs can show data but do not usually declare what was omitted due to context budget. | Omission accounting and fail-closed safety-floor rules. | Prevents unsafe agent confidence when key contraindications or obligations were left out. | Problem list, allergies/constraints, orders/MAR, labs | v0.5 spec prep lines for fail-closed safety predicates | Overbuilding policy before profiles exist. | PRD/issue: safety-floor profile draft |
| GAP-003 | Summaries often hide source-to-summary transformation. | Provenance-linked compression/summary with claim ids, hashes, and transform lineage. | Clinician can audit why a summary says what it says. | Notes, handoff, audit/provenance | `memoryProof` evidence sections; ADR017 governance | Excessive complexity if added before deterministic grammar. | ADR candidate after ContextPacket |
| GAP-004 | Contradictions and uncertainty are scattered across notes, labs, and assessments. | First-class uncertainty/contradiction projection tied to evidence. | Safer handoff and escalation because unresolved uncertainty is visible. | Labs, diagnostics, assessments, notes | ADR016 memory proof sections; Phase A trajectory/evidence pack | False certainty if unsupported heuristics generate uncertainty. | PRD/issue: uncertainty/open-loop projection |
| GAP-005 | Agent output can look like chart truth unless review state is explicit. | Proposed-claim and human review workflow with accepted/rejected/deferred states. | Keeps nurse/clinician authority clear and reduces unsafe automation pressure. | Authorship, signatures, audit, orders | ADR017; foundation decision register FDR-006 | Direct accepted writes or ambiguous review authority. | ADR/PRD: agent proposal and review policy |
| GAP-006 | Agents need proof of exactly what context they saw at a time. | ContextReceipt referencing packet hash, query time, compiler version, and claim hashes. | Enables replay, accountability, and debugging of agent recommendations. | Audit/provenance, API/export | v0.5 package adoption map and spec prep | Receipt becomes mistaken for clinical fact. | ADR: ContextReceipt semantics |
| GAP-007 | EHR search/navigation is not optimized for hot/warm/cold task context. | Access model separating hot current packet, warm evidence chain, and cold source-linked history. | Less clinician cognitive load and safer agent prompt construction. | Full chart navigation, history, notes | Phase A hot/warm/cold access model | Backend/vector decisions chosen too early. | PRD/issue: access behavior only, backend deferred |
| GAP-008 | Clinicians duplicate the same bedside fact into note, handoff, review, and tasks. | Chart-once/project-many projection contract. | Reduces documentation burden while keeping outputs evidence-linked. | Notes, flowsheets, handoff, care plan | ADR016; clinical-reference broad skeleton | Derived projections treated as truth. | PRD/issue: projection contract and non-authority guardrails |
| GAP-009 | Legacy EHRs do not define a bounded LLM read surface with explicit tool grants. | Read-only access plane/MCP tools over approved projections, no direct chart mutation. | Allows useful agent help while preserving clinical authority and least privilege. | APIs, audit, role policy | v0.5 access-plane planning | Tool surface grows before chart primitives settle. | Future ADR: access plane / MCP boundary |
| GAP-010 | Worklists can become punitive, noisy, or automation-biased. | Nonpunitive shift/workflow projection with due windows, blocked/deferred/carry-forward semantics, and disable-able suggestions. | Helps nurses prioritize without implying blame or autonomous completion. | Task/worklist, handoff, orders | shift-brain strategy; HITL workflow decisions | Handoff/worklist tunnel vision defines core substrate. | PRD/issue: workflow projection semantics |
| GAP-011 | Standards can export records but do not define LLM prompt context quality. | Standards-boundary adapters plus internal context compiler tuned for agent navigation. | Reuses standards while giving agents usable, bounded, evidence-linked packets. | FHIR/openEHR/API/export | foundation decision register FDR-001 | Either standards lock-in or reinvention. | ADR: standards posture and adapter boundary |
| GAP-012 | Clinical compliance burden is often manual and retrospective. | Governance projections: review state, attestation, late-entry/correction visibility, audit summaries. | Offloads documentation headaches without claiming certification. | Signatures, audit, corrections, notes | ADR017; review-attestation pack | Legal/product claims exceed evidence. | Future ADR map: governance/accountability scope |
