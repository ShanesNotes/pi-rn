**Category:** enhancement
**Summary:** Inventory the current `pi-sim` public telemetry publication responsibilities before any Module seam is designed.

**Current behavior:**
The public telemetry producer contract is already documented and tested, but maintainer-facing publication responsibilities are distributed across provider-facing types, runtime orchestration, file-lane publication, public docs, manifest metadata, and regression checks.

**Desired behavior:**
An AFK agent should produce a concise responsibility inventory at `.scratch/pi-sim-public-telemetry-publication-module/publication-responsibility-inventory.md` that names the current publication surfaces, separates hidden simulator implementation from public telemetry output, and identifies what must remain producer-owned before later regression-lock or Module-interface work proceeds. The inventory should end with a `Next gate recommendation` section that recommends which downstream issue, if any, should move next based on the evidence gathered.

If the inventory discovers README/manifest/test/source mismatches, record them as follow-up findings in the inventory instead of fixing them in this issue.

**Key interfaces:**
- Public telemetry Interface authority: `pi-sim/vitals/README.md` plus `pi-sim/vitals/.lanes.json`.
- Hidden/public boundary: provider internals, scenario secrets, validation evidence, latent findings, future schedules, scoring keys, and Pulse internals must not become consumer dependencies.
- Simulation time boundary: `pi-sim` owns canonical simulation clock values; sibling consumers may preserve/display public timestamps but must not rewrite them.
- Inventory classification buckets: Hidden runtime implementation, public telemetry construction, public file-lane publication, public contract authority, and regression evidence.
- Evidence style: every bucketed responsibility should cite current file paths and stable section/symbol names where possible; avoid fragile line-number-only references.
