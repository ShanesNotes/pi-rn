## Goal

Generate a single static `dashboard.html` from `docs/plans/kanban-prd-board.md` that displays the kanban board as four vertical columns (`Backlog`, `Ready`, `In Progress`, `Done`) of cards, where each card shows its ID, one-line title, and a small status pill. The dashboard's job is to let a non-technical user open it in a browser and understand the backlog state in a 3-second glance — no clicks, no server, no live refresh.

## Constraints

- Static HTML output only — no server, no SPA, no client-side JS framework. Plain HTML + minimal embedded CSS.
- Self-contained file — viewable via `file://` URL by double-click in any browser. No external CDN dependencies; inline all CSS.
- Generated by an `npm run dashboard` script (added to `pi-chart/package.json`); regen is manual after board edits, not live-watch.
- Source of truth is `docs/plans/kanban-prd-board.md` only. The script must not re-read other files.
- Output written to `docs/plans/dashboard.html`.
- No new runtime dependencies in `pi-chart/package.json` (use the existing `tsx` + node stdlib path; a tiny markdown table parser is acceptable, or hand-roll one inline).
- Must not modify any source code under `src/`, `schemas/`, or `patients/` — this lane is docs/build-tooling only.
- Must not collide with codex's active edits to `docs/plans/kanban-prd-board.md` itself (we read it; we do not write to it).
- Mobile or print rendering is not a target — desktop browser only.

## Non-goals

- No clickable card detail / drill-down / link expansion.
- No "next action" highlighting, no change-since-last-time deltas, no activity feed.
- No backend, no API, no database.
- No live file-watch / auto-refresh.
- No theming options, dark mode toggle, or user preferences.
- No card editing, drag-and-drop, or board mutation. Read-only render.
- No commit hooks or CI integration in this iteration.

## Acceptance criteria

- [ ] `npm run dashboard` produces `docs/plans/dashboard.html` with no runtime errors.
- [ ] The HTML opens in a desktop browser via `file://` and renders without external network requests.
- [ ] The page contains four columns headed `Backlog`, `Ready`, `In Progress`, `Done`, with visible counts in parentheses.
- [ ] Every card from the source board's `Done / accepted evidence`, `Ready for PRD execution`, `Ready for tracer execution after HITL selection`, and `Backlog converted to thin PRD/test-spec surfaces` sections appears in the right column.
- [ ] Each card renders its identifier (e.g. `PHA-001`), its one-line title, and a small status pill derived from the board's Status / Outcome column text.
- [ ] Counts in the column headers equal the number of cards rendered in that column.
- [ ] When the source markdown is edited and `npm run dashboard` is re-run, the HTML reflects the edits (no stale cache).
- [ ] A node test (`scripts/dashboard.test.ts` or similar) verifies the four columns + counts + at least one canonical card per section using a sample fixture or the live board.
- [ ] No new runtime dependencies appear in `pi-chart/package.json` `dependencies` block.
- [ ] No files outside `pi-chart/scripts/`, `pi-chart/docs/plans/dashboard.html`, and `pi-chart/package.json` are modified.

## Status-mapping rules (column source)

| Dashboard column | Source board section(s) |
|---|---|
| Backlog | `Backlog converted to thin PRD/test-spec surfaces` |
| Ready | `Ready for PRD execution` + `Ready for tracer execution after HITL selection` |
| In Progress | (no current source section — column renders empty until a future board section is added) |
| Done | `Done / accepted evidence` |

The dashboard build must tolerate the `In Progress` column being empty (count `0`, no cards).

## Card-content extraction

For each card row in a section's table, extract:
- **ID** — first table column, before the first space (e.g. `PHA-001`).
- **Title** — remainder of the first column after the ID.
- **Status pill** — the `Status` (Backlog table) or `Outcome` (Done table) column text, truncated to ~30 chars; if absent, fall back to the section name.
