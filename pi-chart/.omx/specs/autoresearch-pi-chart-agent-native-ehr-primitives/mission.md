# Mission: improve pi-chart primitives for an agent-native EHR

## Question
How should pi-chart evolve its load-bearing primitives so it remains append-oriented and provenance-rich, while becoming a better substrate for an autonomous clinical agent operating as an EHR-native actor?

## Desired output
A grounded recommendation report that:
1. identifies the strongest current primitives worth preserving,
2. names the most important primitive gaps,
3. proposes a ranked improvement set with rationale, tradeoffs, and sequencing,
4. distinguishes repo evidence from external standards guidance.

## Constraints
- Respect pi-chart's stated design center: not an EHR clone, but an agent-facing durable clinical memory substrate.
- Prefer changes that preserve the current event-stream thesis unless a primitive change is clearly justified.
- Use repo-local sources first; use external primary sources only for standards-informed framing.
- Focus on primitives, not UI or importer implementation.
