# Context Snapshot — ADR 015 Phase 1 merged

## Task statement

Execute merged Phase 1 of ADR 015 in one commit: schema `$defs.EvidenceRef`
+ envelope additions plus types and parser normalization for ADRs 009/010/011.

## Desired outcome

- `schemas/event.schema.json` documents the new envelope surface without
  adding validator enforcement early.
- `src/types.ts` exposes the additive type surface needed by later phases.
- `src/evidence.ts` normalizes v0.2 evidence refs into the new canonical
  shape while leaving bare-string inputs valid.
- Existing tests, `npm run check`, and `npm run typecheck` stay green.

## Known facts / evidence

- Current schema still embeds an inline structured `links.supports` object
  and has no `$defs.EvidenceRef`, `links.resolves`, `links.contradicts`, or
  `transform` block.
- Current `src/types.ts` still defines `EvidenceRef` as a union of
  `{kind,event|note|artifact,id}` and `{kind:"vitals",metric,from,to,encounterId}`.
- Current `src/evidence.ts` returns old-style refs with `id` / `metric` fields
  and normalizes `vitals://` URIs to `{kind:"vitals", metric, from, to, encounterId}`.
- `src/views/evidenceChain.ts` is the direct reader of normalized
  `EvidenceRef` today and currently switches on `event | note | vitals | artifact`.
- Existing tests in `src/evidence.test.ts` and `src/views/evidenceChain.test.ts`
  assert the old normalized shape, so Phase 1 must update them even though it
  does not add new behavioral coverage.
- `package.json` verification gates are available as `npm test`,
  `npm run check`, and `npm run typecheck`.

## Constraints

- No validator rule changes in Phase 1.
- No view-behavior changes in Phase 1 beyond whatever is necessary for
  `evidenceChain` to compile against the normalized shape.
- Keep `kind: "vitals"` accepted as a deprecated alias for one release.
- Commit intent line should follow:
  `Phase 1 — schema + types + parser for ADRs 009/010/011 (ADR 015)`.

## Unknowns / open questions

- Whether `EvidenceNode.kind` should stay `"vitals"` while `EvidenceRef.kind`
  becomes `"vitals_window"` in Phase 1. Current assumption: yes, because the
  user requested no view changes and only parser/type/schema normalization.
- Whether helper exports beyond `parseEvidenceRef`, `formatVitalsUri`, and
  `isVitalsUri` are needed immediately. Current assumption: expose only the
  minimum normalization helpers demanded by downstream Phase 2+ work.
