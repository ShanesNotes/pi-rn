§01 · the bet why this exists

Clinical memory is the
durable bet.

Modern charts are mutable rows behind vendor APIs. Audit trails are an afterthought. AI-drafted clinical content arrives with no native way to prove what it said, when, about whom — only legal disclaimers and opaque telemetry.

We bet the durable surface is clinical memory itself: a provenance-rich, append-only event log that gives a clinician or an agent enough observable context to understand what happened, why it mattered, what evidence supports it, and what remains uncertain.

The agent operates under partial observability. It sees what the bedside team would see — monitor output, EHR data, assessment findings — and never the hidden physiology underneath. The same chart serves both readers. The same provenance protects both decisions.

design principle
the chart is canonical · current state is a query · derived summaries are disposable

§04 · pi-ledger · supporting kernel KERNEL · ACTIVE BUILDOUT

Identity is cryptographic.

Every clinical claim becomes deterministic bytes, then a sha256:<hex> record hash, then an append-only ledger entry. pi-chart, the agent, and any future access surface stand on the same identity guarantee.

canonical bytes deterministic representation of any claim module · live
record hash tamper-evident identity · sha256:<hex> module · live
claim shape smallest acceptable shape, validated module · live
append ledger patient-scoped, hash-chained, append-only module · live
predicate registry vocabulary of clinical claims · admitted by policy module · live
bitemporal read what was true at X, as known at Y module · live
why a separate kernel

The cryptographic substrate is built as a sibling subproject, not a feature of the chart. The chart, the agent harness, a future access plane, and any future runtime stand on the same identity guarantee — and a TypeScript port, a WASM build, or a CLI binding can prove it agrees with the kernel by matching one golden hash.

Same claim → same bytes → same hash. Across runs, machines, and implementations. The kernel is hardening across multiple axes — tighter type guarantees, stricter time semantics, cleaner separation between clinical vocabulary policy and append — while the foundational identity guarantees stay stable.

§05 · pi-sim · hidden runtime RUNTIME · STABLE

The patient is hidden.
Only telemetry is public.

A scenario-driven simulator generates synthetic ICU encounters — vitals, alarms, assessment findings — while keeping ground truth private. Consumers see what a bedside team would see. Nothing more.

01 · hidden runtime

What stays private.

Provider routing, scenario time, latent physiology, validation oracles. The Pulse provider runs under a Docker shim; a scripted provider runs Docker-free for tests and demos.

Not exported. Not inspectable. Sibling consumers must never import scripts/ or pulse/.

02 · public contract

What every consumer sees.

  • vitals/current.json latest scalar frame · hr · spo2 · rr · bp · temp · etco2
  • vitals/timeline.jsonl append-friendly history of frames
  • vitals/events.jsonl actions · alarms · assessment requests
  • vitals/waveforms/ optional ECG · ABP · pleth · capnogram
  • encounter/current.json identity · phase · scenario context
  • assessments/current.json reveal-only findings, after request
03 · the bet

Why partial observability.

Real clinicians learn from incomplete information — what a monitor shows, what a nurse observes on bedside exam, what arrives async from labs. Real patient data is legally fenced; static synthetic data is too thin.

pi-sim generates coherent, strategically-timed encounters where ground truth stays hidden for blind validation. Demo scenario: patient_002_septic_shock_recovery — 64 hours of trajectory, scriptable from minute one.

§06 · pi-monitor · display-only consumer RUST · DISPLAY LAYER · SHIPPED

The monitor reads.
It does not write.

The bedside monitor at the top of this page is an illustration of what pi-monitor renders — a native Rust display layer that consumes the public telemetry contract and shows vitals, waveforms, and alarms in a terminal, a static HTML snapshot, or a kiosk window. No chart truth. No simulator mutation.

A display-only consumer is the reference enforcement of the public contract. By owning only presentation, pi-monitor proves the producer can be used independently and forces early detection of schema drift, freshness gaps, and waveform availability holes — before any chart-side adapter has to absorb them.

§07 · pi-agent · draft workspace inside the chart ALPHA TARGET · REVIEW-GATED

The agent does not replace the chart.
It works inside chart memory.

For v0.5 alpha, pi-agent is presented through the Agent Canvas: a bounded workbench for organizing context, drafting handoff/SBAR/addenda, and surfacing open loops. The chart remains canonical. Drafts become chart truth only through clinician review and commit.

What the agent reads

bounded context
  • 01
    current safety frame Patient, encounter, as-of chart clock, active constraints, watcher state, and open obligations.
  • 02
    source-linked projections Timeline, trend, evidence chain, open loops, narrative, and future ledger-backed ContextPacket surfaces.
  • 03
    public observations only Monitor telemetry and charted bedside findings. No hidden simulator physiology, scenario oracle, or raw patient-directory spelunking.
  • 04
    freshness boundaries If vitals shift or source claims are revised, draft artifacts become stale instead of silently staying trusted.

What the agent creates

scratchpad artifacts
  • 01
    handoff draft A source-linked summary of what changed, what is open, and what the next clinician must watch.
  • 02
    SBAR / escalation draft Structured communication that cites vitals, labs, notes, and active obligations.
  • 03
    review prompts “This result is unreviewed,” “this reassessment loop is due,” “this medication action is blocked by scan/attestation.”
  • 04
    not final clinical write Generated output is a proposal. The Chart / sign gate belongs to the clinician-facing chart workflow.

What remains blocked

safety boundary
  • 01
    no direct accepted writes The alpha path deliberately avoids silent agent mutation of chart truth.
  • 02
    no MAR administration Medication administration stays behind bedside scan, patient scan / two-ID workflow, and RN attestation.
  • 03
    no hidden-state advantage The harness only works if the agent sees what the bedside team could see.
  • 04
    no separate clinical memory Long-horizon context routes back through chart memory and future ledger-backed packets, not an opaque side database.
Alpha stance: pi-agent is valuable because pi-chart makes it safe to be useful. The showcase should sell the chart cockpit first: source-linked clinical memory, then review-gated agent assistance.
